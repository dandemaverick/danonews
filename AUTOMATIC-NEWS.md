# Automatic news research

Open `/admin/automation` (also linked from the newsroom). This workflow is paused by default. Add `OPENAI_API_KEY` as a **secret** to the `danonews` Cloudflare Worker and enable the workflow from that page. Never add API keys to Git or to chat. API billing is separate from ChatGPT. Four research attempts per UTC day is the initial hard limit; each request permits at most five web-search tool calls and 6,500 output tokens. This is a request cap, not a monetary spending guarantee; set provider-side budgets as appropriate.

The existing 15-minute cron refreshes RSS, then processes one queued story. The workflow only considers stories dated within 48 hours. It researches the event through the OpenAI Responses web-search tool, writes an original report and verifies that paragraph citations occur in the returned research source list. It requires two cited publisher hosts and the model's explicit independence assessment; this does not guarantee factual accuracy or independent ownership.

Incomplete responses, unsupported citations, insufficient material and provider errors produce a review entry, not a published article. Supported sensitive reports are saved as drafts. Other reports can publish automatically only while the switch remains enabled. Automated reports have no copied cover image and advertising eligibility defaults off. Existing editorial posts are never overwritten. Source links and an automated-research disclosure appear beneath the report, with inline citations for unchanged paragraphs. Original feed story URLs redirect to their published reports.

Activity and provider configuration state appear at `/admin/automation`. Review drafts in `/admin`. Pausing prevents further work and is checked again before publication; an in-flight provider request can still incur usage and finish as a draft. Crashed research jobs are held for review instead of being automatically retried. Duplicate event keys are rejected transactionally, though differently phrased model keys may still need editorial duplicate review.

Deployment must apply `drizzle/0003_auto_news.sql` before the new workflow runs. It only adds two tables and an index. No API connection or live generation has been validated by offline tests. Tests exercise mocked research responses, real SQLite inserts/transactions, quota handling, provenance validation, draft gates and idempotency.
